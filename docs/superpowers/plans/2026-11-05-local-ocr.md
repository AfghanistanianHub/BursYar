# Local OCR implementation plan

Goal: replace runtime OCR CDNs with checksum-verified, pinned same-origin assets, without enabling production binaries or triggering remote operations.
Spec: Mission 29 user instructions; reuse Mission 28 candidate 2f8356f.
Architecture: exact npm packages and lock integrity provide build inputs; a deterministic preparer verifies a checked-in SHA-256 allowlist and copies assets/licenses to ignored public/vendor/ocr-v1. A lazy runtime passes explicit same-origin worker/core/language paths and disables persistent OCR caches. Existing deadlines, consent/review and production gate remain.

Constraints: no inference, remote CI, PR, deployment, project settings, student data or laptop. Native implementation authorized by user; no design approval pause.

1. Write failing extractor test asserting explicit local worker/core/language options. Write failing asset preparation tests for byte tampering/missing assets and unexpected package versions.
2. Implement local asset preparer, hash manifest, runtime paths and worker options. Pin dependencies. Run focused and whole Node suite.
3. Replace CDN integration assumptions with same-origin-only requests, actual synthetic PNG/JPEG/scanned-PDF OCR and en/fa/ps evidence; test unavailable assets, invalid PDFs and retained consent/review. Preserve production binary gate.
4. Address bounded resources and cleanup regressions found by tests. Do not claim hard process memory caps on browser WASM.
5. Review completed diff independently. Save code as GitHub commit objects without refs; update Issue120, report remaining persistence and release risks.

Review focus: nested worker CDN defaults; corrupt/missing models; post-timeout workers; compressed-data expansion; multilingual OCR quality vs manual review. Real OCR tests must distinguish recognition from manual transcription.

Ruling: generated vendor binaries are reproducible ignored build outputs, not large git blobs. Dependency lock plus asset SHA-256 manifest retain exact bytes. If dependencies cannot be fetched or integrity verified, preparation fails closed and TXT remains usable.
