# URL-first reliability and demo recovery

## Integration

Draft functional work is stacked on visual-design PR #15 (`feat/minimal-student-journey`), retaining PR #14 and #13. #15 started before #14's final response-byte/BOM digest fix; the functional branch explicitly includes #14's final ancestry as well. The design's single-column layout, progressive disclosures, private profile/TXT pipeline, evidence compiler, Meta model/schema/spending gates and immutable scenarios are preserved. No PR was merged, no production settings changed, and no deployment or paid inference occurred.

## What a student sees

One URL field and one primary fetch action remain the entry point. The optional paste action is secondary. When a site refuses retrieval, the URL stays unchanged and the translated message offers one primary recovery action: paste the relevant source text. Opening the official page in the student's own browser and importing a saved HTML/TXT page live under Other options. Technical codes, provider diagnostics and signatures are not shown to students. Evidence details remain collapsed.

Every path joins the same source-review/approval UI and `/api/analyze` endpoint, exact-evidence validation, profile comparison, missing-evidence guidance and counterfactual implementation. Importing or fetching alone never calls Meta or reserves inference quota. Pasted text remains editable; an imported/fetched preview is read-only until the student chooses to paste/edit. Changing text invalidates provenance and approval. Changing a URL associated with a preview clears its text. Source changes cancel pending analysis and clear the old assessment. Language changes preserve the URL, supplied/fetched preview, approval and current recovery/manual-entry state.

## Provenance and input boundaries

- `server_fetched`: the secure fetcher really received a permitted public page. The receipt retains requested/final URL, retrieval time, redirects, raw response-byte digest, extracted-text digest and method. This is traceability, not institutional certification or a guarantee of policy completeness.
- `user_supplied_html` / `user_supplied_text`: the student supplied a saved public page. `retrievedAt` is null; the server records the supply time. The URL is the student's attribution, not evidence that BursYar retrieved or authenticated that page. The file's original bytes and extracted text have separate digests. Filename/mtime are not treated as verification evidence.
- `user_pasted_text`: manually pasted text remains a user attribution. The validated analysis records its submitted-text digest and supply time with no retrieval timestamp.

Imported/fetched receipts are HMAC-signed, bound to the Firebase-derived user identity through a keyed opaque binding, and expire after 30 minutes or server restart. A different user, modified text, changed URL or altered origin cannot reuse them. User identifiers and signatures are never logged or sent to Meta. The analysis response exposes `sourceProvenance` for all paths and only includes `retrieval` for an actually server-fetched receipt. Supplied pages can never promote a profile fact to issuer-verified.

The saved-source endpoint requires Firebase authentication and the same origin rules as analysis. JSON is bounded at 400 KiB; canonical base64 decodes to at most 256 KiB, and only strict UTF-8 HTML/TXT is accepted. NUL/binary controls and invalid encodings are rejected. Extracted text must fit the existing 30–12,000-character analysis bound. There is no silent clipping. Imports have a separate five-request-per-user-per-minute bound and bounded rate map, leaving the existing five-per-minute network-fetch limit intact. Existing gateway concurrency remains two.

Saved HTML is parsed as data with parse5. No DOM from it is installed in the app; no scripts, images, forms, frames, redirects or embedded resources execute or load. Scripts, hidden inline content and navigational/active elements are omitted; canonical/base/meta tags cannot change the attributed URL. Same-site links remain optional manual suggestions. Visible malicious instructions are retained as untrusted source data and pass through the same isolated evidence prompt; this does not claim perfect semantic prompt-injection resistance.

The HTML/TXT source importer is for public scholarship pages. It does not replace or expand the separate private educational-document workflow. Files are processed in memory, not stored in the document DB or sent raw to Meta. Only reviewed extracted source text enters the existing inference prompt after explicit UI approval. PDFs/images remain unsupported source imports.

## Deterministic evidence versus live evidence

All automatic tests are offline. `https://university.example/award`, `https://university.example/blocked`, `https://example.com/`, `https://evil.example/` and `https://malicious.invalid/` are fixture/malicious-input strings only, never genuine scholarship retrieval evidence. The offline public-university fixture also uses the Oxford Law URL with a synthetic transport; it is explicitly labeled offline and is independent of the live ledger proving that actual URL was genuinely fetched. Browser identity and Meta are mocked. The real local source/import/document/profile APIs are exercised, and HTTP tests independently exercise the real existing analyzer/evidence/compiler pipeline with a fake provider.

Tests cover successful public HTML, header/body Cloudflare challenges, bounded UTF-8/base64, malicious canonical/base/active/hidden HTML, exact file/text digests, owner-bound receipts, tampering, expiry, authentication/origin rejection, prompt boundary integrity, no spending on preview, and all three source paths into analysis. The browser matrix adds challenge recovery, original-URL retention, one primary action, saved HTML/TXT, no script/resource execution, continued eligibility/next steps, and state/localization across English/Dari/Pashto. Browser screenshots carry an offline rehearsal banner. Automated translation checks are not fluent human approval.
